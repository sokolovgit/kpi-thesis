# Дипломний проєкт і курсова (КПІ ФІОТ, кафедра ІПІ) у LaTeX

Інструмент — репозиторій [kpi-thesis](https://github.com/sokolovgit/kpi-thesis): клас
`kpi-thesis.cls` з пакетами `kpi-titles`, `kpi-graphics` (тека `tex/`), шаблони (`templates/`),
лінтер нормоконтролю (`scripts/check.py`) і `justfile`. Збирання — XeLaTeX.

Основа — формат диплома кафедри ІПІ 2026 року, що пройшов нормоконтроль, з виправленнями
зауважень, які в ньому знайшлися. Правила: методичка кафедри 2024 → ДСТУ 3008:2015 → ДСТУ 8302:2015 → ЄСПД.
Повний перелік з номерами пунктів і посиланнями: `references/requirements.md`.

## Де лежить репозиторій

Клас встановлено в TEXMFHOME (симлінк, на Windows — junction або копія з файлом `.repo`),
тож корінь репозиторію знаходиться так:

```sh
[ -d /Library/TeX/texbin ] && PATH="/Library/TeX/texbin:$PATH"
cls=$(kpsewhich kpi-thesis.cls) && dir=$(dirname "$cls") \
  && repo=$(cat "$dir/.repo" 2>/dev/null || (cd "$(dirname "$(realpath "$cls")")/.." && pwd)) \
  && test -f "$repo/justfile" && test -d "$repo/templates" && echo "$repo"
```

- Порожньо або `kpsewhich` немає — це перший запуск: прочитати `references/setup.md` і пройти його.
- Клас знайдено, а репозиторій ні — запитати користувача, куди клоновано.
- Усередині роботи шлях до репозиторію вже записаний у її `justfile` (`KPI := '...'`).

**Чи клон свіжий.** Плагін (цей скіл) і клон із класом оновлюються окремо, тож один раз за
сесію перевірити:

```sh
git -C "$repo" fetch -q origin 2>/dev/null && git -C "$repo" rev-list --count HEAD..@{u} 2>/dev/null
```

Більше нуля — сказати, скільки комітів бракує, і запропонувати оновлення. Порожньо (немає
мережі чи upstream) — пропустити мовчки.

**Оновлення класу зачіпає всі роботи одразу** (клас підключено симлінком). Тому:

1. Показати, що зміниться: розділ нових версій у `$repo/CHANGELOG.md`, особливо «Перехід».
2. Попросити закомітити роботи, над якими йде робота.
3. `git -C "$repo" pull` (на Windows з копією класу — ще `just install`).
4. У кожній роботі: `just all` (курсова — `just build`) і `just check`; прибрати з преамбули те,
   що за «Переходом» тепер робить клас.

Робота, що вже на здачі, не мусить оновлюватися: `just freeze` у ній копіює поточний клас у
`tex/` роботи, і `git pull` її більше не змінює (повернути — `rm -rf tex`). У роботі, створеній
до v1.3, рецепта ще немає: `cp -R "$repo/tex" tex` і рядок
`ensure_path('TEXINPUTS', './tex//');` у `.latexmkrc` (у дипломі — `'../tex//'`).

## Нова робота

```sh
cd "$repo"
just new diploma ~/kpi/diploma        # або: just new coursework <dir>
cd ~/kpi/diploma
# заповнити meta.tex (курсова — шапку main.tex)
just all        # усі документи + зведений build/<Прізвище>_<група>.pdf
just check      # перевірки нормоконтролю
```

Ім'я зведеного PDF береться з `meta.tex` (прізвище зі `student-stamp` і `group`), у курсовій —
з `student` і `group` у `main.tex`.

## Робочий цикл

Після кожної зміни тексту, яку робиш у роботі:

1. `just build <doc>` (курсова — `just build`); у кінці — `just all`.
2. `just check`.
3. Виправити все, що він знайшов, і повторити з кроку 1.

Збірка впала — `just build` показує перші помилки з журналу. Після двох збірок одночасно
(наприклад, `just watch` і `just all`) або дивних помилок у `.aux` — `just clean-aux`.

Не казати, що документ готовий, поки `check` дає помилки, крім заглушок `\todo`, які
користувач ще має заповнити сам. Попередження показати й пояснити, а не мовчки ігнорувати.

## Структура диплома

| Папка | Документ | Шифр |
|---|---|---|
| `title/` | титул, завдання, анотації укр/англ, відомість | `.00.90` |
| `specification/` | технічне завдання | `.01.91` |
| `explanatory-note/` | пояснювальна записка (`chapters/*.tex`) | `.02.81` |
| `source-code/` | текст програми | `.03.12` |
| `test-plan/` | програма та методика тестування | `.04.51` |
| `user-manual/` | керівництво користувача | `.05.34` |
| `graphics/` | графічний матеріал (А3) | `.06.99` |

- **`meta.tex` — єдине джерело** теми, ПІБ, шифрів, дат наказу. Жодних шифрів і дат руками в
  документах: інакше дата наказу легко розходиться між завданням і ТЗ.
- **Числа рахуються самі.** Кожен документ збирається у свою `build/` і пише туди `<doc>.kpistats` (сторінки, рисунки, таблиці,
  джерела, додатки). Титул бере їх для анотації (`\kpiAnnotationStats`) і відомості.
  Тому `title` збирається останнім — `just all` це робить.
- `just build explanatory-note`, `just watch explanatory-note` — один документ; `just stats` — числа.

## Команди класу

| Що | Як |
|---|---|
| Структурний елемент без номера | `\structural{ВСТУП}` |
| Нумерація сторінок після титулу | `\mainmatter` |
| Таблиця з «Продовження таблиці N» | `\begin{kpitable}{|L{4cm}|L{10cm}|}{Назва\label{tab:key}}{\textbf{А} & \textbf{Б}} ... \end{kpitable}`; підпис і шапка не лишаються самі внизу сторінки (`[N]` — скільки рядків тримати разом, типово 5, `[0]` — вимкнути) |
| Комірка по лівому краю без переносів | тип колонки `L{4cm}` (`p{}` — по ширині, з переносами) |
| Пояснення до формули | `\begin{where} M & маса, кг; \\ F & сила, Н. \end{where}` |
| Переліки | `itemize` → «–»; `enumerate` → «а)», вкладений → «1)» |
| Додатки | `\appendices`, далі `\appendix{Назва}` або `\appendixpdf{Звіт подібності}{../media/report.pdf}` (шлях — від файлу документа) |
| Код у тексті програми | `\codefile{path}{задача}` + `\codeinput[firstline=..,lastline=..]{../../repo/file}`; код у тексті — середовище `Verbatim`. Обидва — `fvextra`, 8 пт (`fontsize=` змінює). `listings` під XeLaTeX псує кирилицю в коментарях |
| Псевдокод | `\kpisetup{algorithms}`, далі `algorithm` + `algpseudocode`: «Алгоритм 1.1 – Назва» |
| Аркуш А3 | `\diagramPage{ССВ}{Назва схеми}{file.png}` або `\graphicsSheet{код}{назва}{вміст}` |
| Заглушка | `\todo{...}` — червона в PDF, `just check` рахує |

Рисунки й таблиці за замовчуванням `[H]` (стоять де написані). Картинки — у `media/`.

## Курсова

- **Склад розділів — з методички курсової своєї дисципліни.** Шаблон узято з диплома (аналіз,
  проєктування, реалізація, тестування); у курсових з інших дисциплін (моделювання тощо)
  розділи зовсім інші — спершу прочитати методичку й перебудувати `chapters/`.
- **Де методичка курсової розходиться з дипломною** — `\kpisetup{...}` у `main.tex`, не
  ручні `\geometry` / `\setlist`:
  `left-margin=20mm`, `hyphenation=false`, `enumerate=arabic`, `table-caption=left`,
  `appendix-title=inline`, `algorithms`, `url-breaks=anywhere` (дуже довгі адреси). Кожну опцію — з коментарем, на який пункт методички
  вона спирається. Це єдине місце таких рішень: не дублювати їх в інших нотатках, бо
  розійдуться.
- **Обсяги розділів** перевіряє `just check`, якщо в `main.tex` є рядок
  `% check: chapter-pages=3-15, intro-pages=1-4` (межі з методички).
- Номер залікової книжки — `gradebook` у `\kpiset`.

## Як писати

- **Тільки коротке тире** `--` (–). Довге `—` check позначає.
- **Десяткова кома**: `62,1~\%`, не `62.1`.
- **Формула — частина речення**, після неї «де» без двокрапки (`where`). Нумерувати лише ті,
  на які є посилання (`\eqref` / «(1.2)»).
- **На кожен рисунок і таблицю — посилання в тексті** («на рисунку~\ref{fig:x}»,
  «(таблиця~\ref{tab:x})»). Діапазон `\ref{a}--\ref{b}` покриває все між ними.
- **Без дужок у дужках**: «за формулою (2.8)», а не «(формула (2.8))»; кортежі й номери
  всередині дужок — перефразувати.
- **Джерела — у порядку першої згадки** (`thebibliography` руками, ДСТУ 8302, мітка `1)`).
- **Кожен розділ закінчується** `\subsection{Висновки до розділу}`.
- **Вступ ≤ 4 с., розділ 1 ≤ 30 %, основна частина 60–70 с.**; анотації ≤ 1000 знаків, 3–10
  ключових слів, однаковий зміст укр/англ.
- **Тема** — дослівно як у наказі. **ОП** — «Інженерія програмного забезпечення інформаційних систем».
- **Числа в тексті — з реальних прогонів**, а не з голови; суми й частки мають сходитися
  (наприклад, кількості в анотації й у розділі тестування).

## Перед здачею (нормоконтроль)

- [ ] `just check` без помилок; попередження переглянуті
- [ ] тема збігається з наказом; номер і дата наказу правильні (денна/заочна/поновлені різні)
- [ ] на титулі є керівник (рецензента можна пізніше); консультант і нормоконтроль у штампах
- [ ] календарний план заповнений (`\kpiCalendarRows` у `meta.tex`)
- [ ] усі частини: титул, завдання, 2 анотації, відомість, ТЗ (з прототипами екранних форм!),
      ПЗ + звіт Unicheck, текст програми, ПМТ, КК, графічний матеріал (≥ 3 аркуші)
- [ ] шифри в штампах графіки відповідають типу схем (ССВ, ССМ, СБД, КЕ…)
- [ ] у PDF немає «??» (усе зібрано через `just all`)
- [ ] зведений PDF з `build/` — саме він іде на нормоконтроль

## Рецензування перед здачею

`just check` ловить оформлення, а не зміст. Перед здачею (диплома чи курсової) запропонувати
користувачу три проходи — вони знаходять те, чого не ловить жоден лінтер:

1. **Розділи окремо, без контексту автора.** На кожен розділ — окремий агент, який бачить
   лише PDF/текст розділу й методичку: чи відповідає вимогам, чи сходяться числа, чи є
   твердження без підстав.
2. **Наскрізне читання всієї записки:** суперечності між розділами, анотація проти тексту,
   висновки проти результатів, однакові назви й позначення.
3. **Рецензент «від імені керівника / лектора»:** які питання поставив би на захисті, що
   назвав би невідповідністю методичці.

Знахідки — списком з місцем у PDF; виправляти після підтвердження користувача.
